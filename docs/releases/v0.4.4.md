# YanFlow v0.4.4

修复启动或闲置后 `Ctrl+Win` 首次按下可能无法开始录音的问题。

- 移除重复的异步按键状态判断：监听已经确认按下时，不再让尚未更新的
  `GetAsyncKeyState` 丢弃此次启动。结束按住录音也使用监听状态。
- 将低级键盘监听移至独立线程。回调只更新状态、投递消息并返回，避免界面中的
  焦点查询、录音设备操作、文件操作等阻塞监听。启动先等待监听安装完成。
- 录音开始时只记录目标窗口和应用，文本框类型检查推迟至输出；原生文本框已经可判定时
  直接使用结果，减少首次调用或长时间闲置后 UI Automation 的等待。
- 在按键状态稳定后补遗漏的松键；闲置无按键时刷新监听，并在解锁或恢复运行时同步。
  轮询只修复释放状态，不启动录音；注入按键仍不能触发快捷键。
- 上一段录音清空时保留新启动请求。仍按住时清空后启动，松开则取消，避免需要再按一次。
  `Ctrl+Win+Shift` 实时开关保留；补第三个 Shift 时沿用已开始的采集。
- 新增不依赖麦克风的首次按键、线程调度、界面阻塞、遗漏松键、恢复通知、等待清空、
  提前松键取消、注入输入排除和按住/实时切换回归，并纳入 GitHub 构建检查。

Windows 对低级键盘回调的时序和超时行为见
[Microsoft LowLevelKeyboardProc 文档](https://learn.microsoft.com/en-us/windows/win32/winmsg/lowlevelkeyboardproc)。

本机没有麦克风；新回归使用模拟按键和采集，音频回归使用已有录音。
未执行物理快捷键、真人录音、实际睡眠唤醒或长时间闲置验证。
ZIP 仍未签名，首次运行可能有 SmartScreen 提示。
