# 按住录音的分段预处理

按住录音超过 8 秒后，应用在现有识别线程空闲时，提前识别已经确定边界的完整分段。预览和最终识别任务优先；每个分段之间重新检查任务队列。音频采集回调不执行推理，不新增推理线程、模型或用户开关。

预处理缓存保存原始 ASR 文字和相对时间戳，不保存词典纠错后的文字。松开后仍走原有分段、时间戳合并、词典处理和目标焦点核验路径。只有录音会话、分段位置、完整 PCM 样本和请求参数完全一致时才复用；不使用哈希相等来代替音频内容核对。失败或不匹配时照常识别。

仍在变化的末尾分段不提前缓存。短录音不启动预处理。缓存只在识别线程中读写，最多保存 12 个不超过 8 秒的分段，最终识别结束后清空。气泡仍展示预览识别，正式文字仍在松开后提交。

## 回归与性能验证

先执行 `build\windows\build-yanflow.cmd`。其中 `--accuracy-smoke` 包括静音/强制边界的完整分段稳定性、重复 token、跨会话隔离、音频变化和参数变化的缓存拒绝检查。

执行 `build\windows\test-yanflow-prepared.cmd`：使用上游公开录音及重复拼接的长录音，按真实时间回放 PCM，经应用端点、预览、最终识别和原生 Edit 输入框完成开关对照。测试期间需要让测试输入框保持前台；失焦时应报交付失败，不能绕过产品焦点保护。

可增加 `--repeats 3` 并使用自己的 PCM16、16 kHz、单声道 WAV：

```text
py.exe -3 tests\prepared-asr-smoke.py . --wave local\asr-eval\prepared\sample-16k.wav --output local\asr-eval\latency\prepared-results.json --repeats 3
```

`local/asr-eval/` 被 Git 忽略。测试音频只复制到自动清理的临时测试目录，不进入便携包目录。输出包含私人转写，应保存在忽略目录。

对照要求原始文字和词典处理后的文字逐字一致、输入框内容与最终文字一致、松开前无写入、气泡按原逻辑消失。计时从合成的录音停止调用开始，到原生输入框写入并读回核验完成；同时记录识别进程累计 CPU 时间、预处理/复用分段数。长句中位数须至少降低 25%，短句中位数不得增加超过 100 毫秒；默认一轮是烟测，多轮交替顺序用于评估抖动。

这是文件音频的实时回放和测试输入框证据，不代表真人麦克风、物理按键或第三方编辑器的端到端测试。短句保持原有识别路径，不能据此声称所有录音都会加速。
